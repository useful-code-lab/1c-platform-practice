# Master Platform 1C — учебная торговая конфигурация 1С

**Master Platform 1C** — это практический учебный проект на платформе **«1С:Предприятие 8.3»**, в котором на одном сквозном примере показано, как проектировать и связывать между собой основные механизмы прикладного решения: оперативный, бухгалтерский и расчетный учет.

Проект будет полезен тем, кто хочет не просто изучать отдельные объекты 1С по учебным примерам, а **увидеть, как эти объекты работают вместе внутри полноценной конфигурации**.

---

## 🎯 Что можно получить из этого проекта

Если вы изучаете разработку на 1С, этот репозиторий можно использовать как **готовый практический пример для изучения архитектуры конфигурации**.

На его основе можно:

# 🏢 Что моделирует проект

В качестве предметной области используется **учебная торговая фирма**.

В конфигурации присутствуют товары, склады, контрагенты и сотрудники.

На основе этих данных реализованы три взаимосвязанных направления учета:

```text
                   ТОРГОВАЯ ФИРМА
                         │
          ┌──────────────┼──────────────┐
          │              │              │
          ▼              ▼              ▼
   Оперативный      Бухгалтерский   Расчетный учет
      учет             учет          заработной платы
          │              │              │
          ▼              ▼              ▼
      Остатки         Проводки       Зарплата
      товаров         Дт / Кт        сотрудников
```

Это позволяет увидеть, как одна хозяйственная операция может одновременно влиять на разные подсистемы учета.

# 🚀 Основные возможности

## 1. Оперативный учет товаров

Реализован учет остатков номенклатуры с использованием регистра накопления.

При поступлении товара формируются партии.

При реализации система определяет партии для списания по принципу **FIFO — первым списывается товар из первой поступившей партии**.

Таким образом, можно изучить не только простой контроль количества товара, но и задачу определения себестоимости реализованных товаров.

### Что можно изучить

* регистр накопления;
* движения документов;
* контроль отрицательных остатков;
* партионный учет;
* списание по FIFO;
* расчет себестоимости;
* работу с остатками регистра;
* формирование отчетности по остаткам.

---

# 🔒 2. Транзакции и управляемые блокировки

Отдельное внимание уделено вопросам параллельной работы пользователей.

Контроль остатков и списание партий выполняются в рамках одной операции с использованием транзакционного механизма и управляемых блокировок.

Это позволяет на практическом примере изучить проблему, которая возникает при одновременном проведении документов несколькими пользователями.

Можно исследовать:

* `НачатьТранзакцию`;
* `ЗафиксироватьТранзакцию`;
* управляемые блокировки;
* объект `БлокировкаДанных`;
* чтение данных внутри транзакции;
* защиту остатков от параллельного изменения;
* взаимосвязь блокировок и проведения документов.

---

# 📚 3. Бухгалтерский учет

В конфигурации реализован собственный контур бухгалтерского учета.

Создан план счетов с основными счетами:

```text
41 — Товары
60 — Расчеты с поставщиками
62 — Расчеты с покупателями
90 — Продажи
```

Документы формируют бухгалтерские проводки.

Например, поступление товара отражается через:

```text
Дт 41 — Кт 60
```

При реализации формируются операции, связанные с отражением выручки и списанием себестоимости:

```text
Дт 62 — Кт 90
Дт 90 — Кт 41
```

Это дает возможность изучить полный путь от хозяйственного документа до бухгалтерской записи.

---

# 📊 4. Субконто и аналитический учет

Для счетов используется дополнительная аналитика.

В качестве аналитических разрезов применяются, например:

* Номенклатура;
* Контрагенты.

Это позволяет рассматривать бухгалтерские данные не только в разрезе счетов, но и получать более детальную информацию.

На практике можно увидеть, как связаны:

**План счетов → План видов характеристик → Субконто → Регистр бухгалтерии → Отчеты.**

---

# 📦 5. Количественный и суммовой учет

Для товаров предусмотрен не только денежный, но и количественный учет.

Таким образом, система может одновременно отвечать на вопросы:

* сколько товара находится на учете;
* на какую сумму;
* какая себестоимость была сформирована;
* какие партии были списаны.

Это позволяет изучить отличие количественных ресурсов от суммовых ресурсов в механизмах платформы.

# 💰 6. Расчет заработной платы

В проекте реализован отдельный пример использования механизмов расчета.

Созданы:

# 🔄 7. Вытеснение расчетов

Один из интересных механизмов проекта — **вытеснение расчетов**.

Для начислений настроены зависимости по периоду действия.

Например, период больничного может вытеснять соответствующий период основного начисления — оклада.

Это позволяет на практическом примере изучить:

* планы видов расчета;
* виды расчета;
* периоды действия;
* периоды базовых расчетов;
* вытесняющие расчеты;
* регистр расчета.

# 💡 Главная идея проекта

Этот проект создан не как набор отдельных демонстрационных примеров.

Его основная задача — показать **сквозную работу механизмов 1С в рамках одной прикладной системы**.

В реальном прикладном решении пользователь создает документ, а его проведение может одновременно изменить оперативные остатки, сформировать бухгалтерские движения и повлиять на последующую отчетность.

Именно такой принцип и демонстрируется в проекте:

```text
                Пользователь
                     │
                     ▼
                  Документ
                     │
             ┌───────┴───────┐
             ▼               ▼
      Оперативный учет   Бухгалтерский учет
             │               │
             ▼               ▼
     Регистр накопления  Регистр бухгалтерии
             │               │
             └───────┬───────┘
                     ▼
                   Отчеты
```

Дополнительно отдельный контур показывает, как в 1С могут быть реализованы **сложные периодические расчеты**, включая графики рабочего времени, периоды действия и вытеснение начислений.
