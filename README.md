# 1C Platform Practice

**Практическая учебная конфигурация на платформе «1С:Предприятие 8.3»** для изучения механизмов разработки, учета и взаимодействия объектов прикладного решения.

Проект представляет собой **сквозной пример конфигурации учебной торговой фирмы**, в котором объединены оперативный, бухгалтерский и расчетный учет.

Главная задача проекта — показать не отдельные демонстрационные примеры, а **как различные механизмы платформы 1С работают вместе в рамках одной прикладной системы**.

---

## 🎯 Что дает этот проект

Репозиторий можно использовать как **практический учебный стенд для разработчика 1С**.

Вместо изучения механизмов платформы по отдельности можно открыть готовую конфигурацию и проследить полный путь данных:

```text
Справочник
    ↓

    ↓
Регистры
    ↓
Движения
    ↓
Остатки / Проводки / Расчеты
    ↓
```

На примере проекта можно разобраться:

* как проектируются объекты конфигурации;
* как документы изменяют данные регистров;
* как организуется контроль остатков;
* как реализуется партионный учет FIFO;
* как рассчитывается себестоимость товаров;
* как работают транзакции и управляемые блокировки;
* как формируются бухгалтерские проводки;
* как организуется аналитический учет через субконто;
* как одновременно вести количественный и суммовой учет;
* как реализуются периодические расчеты;
* как работает вытеснение расчетов;

# 🚀 Основные возможности

## 1. Оперативный учет товаров

Для хранения остатков используется регистр накопления `ОстаткиНоменклатуры`.

Поступление товаров формирует партии.

При реализации система определяет партии для списания по принципу **FIFO — первым списывается товар из первой поступившей партии**.

На этом примере можно изучить:

* регистры накопления;
* движения документов;
* контроль отрицательных остатков;
* партионный учет;
* списание по FIFO;
* расчет себестоимости;
* получение остатков;
* агрегирование данных.

# 🔒 2. Транзакции и управляемые блокировки

Проект содержит пример защиты данных от проблем, возникающих при одновременной работе нескольких пользователей.

Контроль остатков и списание партий выполняются с использованием транзакционного механизма и управляемых блокировок.

Можно изучить:

* `НачатьТранзакцию`;

* управляемые блокировки;

* взаимодействие транзакций и блокировок.

# 📚 3. Бухгалтерский учет

В конфигурации реализован собственный бухгалтерский контур.

Создан план счетов с основными счетами:

```text
41 — Товары
60 — Расчеты с поставщиками
62 — Расчеты с покупателями
90 — Продажи
```

Документы формируют бухгалтерские проводки.

Например, поступление товара:

```text
Дт 41 — Кт 60
```

При реализации формируются операции:

```text
Дт 62 — Кт 90
Дт 90 — Кт 41
```

Таким образом, можно проследить путь:

```text
Хозяйственная операция
        ↓
Документ
        ↓
Проведение
        ↓
Бухгалтерская проводка
        ↓
Регистр бухгалтерии
```

# 💡 Главная идея проекта

`1c-platform-practice` — это не готовая коммерческая учетная система.

Это **учебная конфигурация для практического изучения платформы «1С:Предприятие 8.3»**.

Основная ценность проекта — возможность открыть реальные объекты конфигурации и увидеть, как они взаимодействуют между собой.

Здесь можно изучать не только отдельные механизмы:

> «Что такое регистр накопления?»

но и более важный для разработчика вопрос:

> **«Как несколько механизмов платформы объединяются в работающий прикладной процесс?»**

Например, реализация товара связывает сразу несколько механизмов:

```text
РасходнаяНакладная
       │
       ├── Проверка остатков
       │
       ├── Поиск партий FIFO
       │
       ├── Расчет себестоимости
       │
       ├── Движения регистра накопления
       │
       ├── Бухгалтерские проводки
       │
       └── Данные для отчетности
```

Именно такие сквозные сценарии позволяют увидеть практическое применение механизмов платформы.
